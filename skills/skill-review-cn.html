这枚做什么

装之前先给一枚 skill 体检：五面逐条挂原文与检索日，缺的点名，装不装留人工。

能力与边界（原文完整描述）

skill 体检报告起草：输入是一枚待装的 skill（本地目录，或商店页／仓库页经解析通道取回的正文），产出是五节报告——被检对象、逐条发现（每条一个 [S#]）、未取到与口径、来源（带 文件:行号 或 URL 与检索日）。Do NOT use for: 替你决定装不装（判断位 [待人工]）、执行被检件代码（只读不跑）、上架与评分。适合装别人 skill 前的初筛、同题对照体检。机检 check_review.py 五道：形制／锚／判决词／覆盖／真跑申报，零网络。五个检查面（声明层／前置层／面文承诺／样例真跑／许可与出处）。Triggers: skill 体检 / 装前检查 / 上架前审

## 四、依赖与两条路的代价

- `python3`：机检与采集器都用它，纯标准库、零网络、不发任何请求。
- 解析辅助 `cue-omni-reader` 是可选的：**不装不报错，代价是体检只剩盘上已有的那一份本地副本**——远端正文读不进来，「远端面文与本地是否一致」那一层永远缺位，报告只能对本地那一份负责。装与不装都先问你要不要用，消耗花之前一定先问。
- 连了通道也不等于取到正文：取数以实际返回为准；截断、只给摘要不给正文、页面改版取不到那段的，一律落第四节点名，不拿常识补。
- 行号会随被检件改动失效：报告里的 `文件:行号` 只在检索日那一刻成立，隔一天重装可能就是另一个形状。

## 五、机检五道与自校验

| 道 | 码 | 卡什么 |
|---|---|---|
| 道一 形制 | `E-FORMAT` | 头部四件自标逐字在位；五节齐且按一二三四五有序；第一节表态位没挂 `[待人工]` 就发红 |
| 道二 锚 | `E-ANCHOR` | 第二节每条发现行末带 `[S#]` 且第五节有对应行；来源行必须同时带 `文件:行号` 或 URL 与检索日 |
| 道三 红线 | `E-BANWORD` | 可放心装／建议安装／建议上架／一定可用／安全无害／不会有问题一类断言零命中（同行挂 `[待人工]` 才放行） |
| 道四 覆盖 | `E-COVERAGE` | 五个检查面各须一条挂锚发现或在第四节点名未取到；第五节一行来源都没有＝没有出处 |
| 道五 真跑申报 | `E-VERIFY` | 写了「真跑通／跑过」就必须同句给出 `cmd=… rc=整数`；没跑就把这行删掉、落第四节 |

逐字节取自该枚包内面文 README.md。词面与包内一致。
