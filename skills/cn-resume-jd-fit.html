这枚做什么

一份简历对一枚 JD 的双向核对：要求逐条挂到简历原话，缺口分两栏点名，不排先后、不下录用结论。

能力与边界（原文完整描述）

简历 × JD 双向核对起草：输入是两份文档（本地文件或解析通道取回的正文），产出四节报告——一句话结论（只说匹配到哪一层）、逐条对齐（每条要求一句、证据一句，各挂 [S#]，两句都须逐字）、缺口两栏（JD 有要求而简历无证据的、简历有内容而 JD 不关心的）、来源（文件:行号 或 URL ＋ 解析日）。机检 check_fit.py 五道：形制与条数带／双锚与定位／两侧逐字回原文／缺口点名／录用与排序断言零命中，零网络。适合岗位对照、转岗材料整理。Do NOT use for: 人评排序、打分、推荐录用或淘汰、批量筛简历。Triggers: 简历对 JD / 岗位匹配核对

## 1、一句话结论

五条要求里四条有逐字证据、一条只有部分证据；这份核对不下录不录的结论。

## 2、逐条对齐

- 要求「三年以上服务端开发经验，主力语言为 Go 或 Java。」[S2] → 证据「用 Java 与 Go 写订单与账务接口，主力语言是 Go。」[S1]，年限另见「林某（虚构），后端工程师，2013 年起从业。」[S1]
- 要求「熟悉至少一种主流 OLAP 引擎的运维与调优。」[S2] → 证据「引擎：参与过一款 OLAP 引擎的查询调优，未负责其部署运维。」[S1]，两半里只有调优那一半有原文，运维那一半简历自己写了「未负责」
- 要求「具备数据分析基础，能写复杂的 SQL 查询。」[S2] → 证据「SQL 写过复杂的多表窗口查询。」[S1]
- 要求「有良好的英文文档读写能力；有小团队管理经验者加分。」[S2] → 证据「英文：能读写一手设计文档，未以英文为工作语言。」[S1]，加分那一半另见「带过三个人的小组半年，负责排期与代码评审。」[S1]
- 要求「能接受每月不超过一次的值班轮换。」[S2] → 证据「负责所上线服务的容量规划，值班轮换每季度参与一次，告警闭环由本组收。」[S1]，这一条按部分证据记，未取到＝更密的轮换能否接受

## 3、缺口与未取到

- JD 有要求而简历无证据的一条：要求「能接受每月不超过一次的值班轮换。」[S2] 只有季度一次的原话（[S1]），每月这一档未取到——问一句就有答案，本件不代答
